People using Plasma choose their own colour scheme: light, dark, high contrast, or something they made themselves.
An app cannot know in advance which colours it will be shown in. So instead of colour values, Kirigami gives you
**roles** such as “normal text” or “background of an error”, and fills in the right value at run time.

You read roles from `Kirigami.Theme`:

```qml
QQC2.Label {
    text: "Could not connect"
    color: Kirigami.Theme.negativeTextColor
}
```

## Colour sets

A window is not one flat colour. The area where content lives is brighter than the window chrome around it, buttons
have their own surface, and a selected row is blue. Each of these surfaces is a **colour set**: the same list of
roles, with different values.

<Example
  name="foundations/colour-sets"
  alt="Seven rounded panels labelled View, Window, Button, Header, Selection, Tooltip and Complementary, each with its own background and text colour"
  caption="The seven colour sets. Each panel uses <code>backgroundColor</code> and <code>textColor</code>; only the set differs."
/>

| Set | Where it is used |
| --- | --- |
| `View` | Where content lives: lists, text areas, the inside of cards. |
| `Window` | The window background around views. This is the default. |
| `Button` | The surface of buttons and similar controls. |
| `Header` | Title bars and toolbars at the top of a page or window. |
| `Selection` | Selected items. |
| `Tooltip` | Tooltips. |
| `Complementary` | A deliberately contrasting area, dark even in a light scheme. Used for overlays on images or video. |

Controls and pages pick their set for you. You only set one yourself when you draw your own surface:

```qml
Rectangle {
    // Use the View colours for this item and everything inside it.
    Kirigami.Theme.colorSet: Kirigami.Theme.View
    Kirigami.Theme.inherit: false

    color: Kirigami.Theme.backgroundColor
}
```

<Callout title="Why inherit: false?" kind="warning">
  By default an item takes its colour set from its parent and ignores its own `colorSet`. Setting
  `Kirigami.Theme.inherit: false` is what makes your choice take effect. Children of the item then inherit the new
  set automatically.
</Callout>

## Colour and meaning

<Example
  name="foundations/colour-status"
  alt="Four status lines: a green tick with Backup finished, an orange triangle with Battery is low, a red cross with Could not connect, and a blue i with 3 updates available"
  caption="Each status is carried by an icon and words. The colour only reinforces it."
/>

- **Use colour sparingly.** A screen where many things are red or orange has no way left to signal a real problem.
- **Never let colour be the only signal.** Roughly one in twelve men cannot tell red from green reliably. Pair the
  colour with an icon, a shape or words, as in the picture above.
- **Keep red for errors and destructive actions.** Do not use it for decoration or for actions that lose nothing.
- **Outline things that float.** A popup or dialog over content needs a contrasting edge, because in dark schemes
  its background is nearly the same as what is behind it. Kirigami's own dialogs and cards already do this.
